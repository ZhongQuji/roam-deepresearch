# 十位顶会评委模拟评审（PSV / verify-before-write 稿，IPM 投稿）

> 依据：2026-10-24 两轮对话里转述的稿件状态（英文稿 v4.1，69 页；中文稿 v4.1，31 页）、已生成的表（tab_profile / tab_gate / tab_roles / tab_growth / tab_prior / tab_expmap）、链 56 / 57 的设计与进度。
> 本评审**没有读到稿件原文**（本机文件通道当天不可用），所有意见针对的是对话里给出的论点、数字和结构；凡是「稿里可能已经写了」的地方都标了「核对」。
> 评委按不同背景设定，每位只给自己最关心的 2–4 条；最后汇总成优先级清单。

---

## R1 · IR / IPM 资深评委（测试集与评测方法论）

**R1.1 样本量与配对检验。** Drafts48 是 48 题 × 6 模型、Drafts199 是 199 题 × 2 模型。「评判分 4 平 1 胜 1 负、落地召回领先 10–15 分」需要：每个模型格位的**配对**（同题）bootstrap 95% CI、配对 Wilcoxon 的 p 值、以及效应量。「平」不能只写「差异不显著」——48 题上不显著很容易，要用等价性检验（TOST，先定一个等价边界，比如 ±3 分）说明「确实差不多」。
→ 修法：一个脚本对 results.jsonl 做配对 bootstrap（题目为重抽样单位，10,000 次），所有主表数字后加 CI；主文一张「效应量 + CI」图代替一部分表。

**R1.2 金证据的来源与一致性。** 31,887 个证据包的「金」由谁定、两人标注的一致率多少（κ 或逐项一致率）、硬负例怎么挑（植入规则）、「未提及」类怎么判。如果金是模型辅助生成再人工复核，要写清复核比例。
→ 修法：数据节加一张「构建流程 + 一致性」表；至少 200 包双标。

**R1.3 「句内落地召回」是新指标，要给它效度证据。** 和人工判断的一致率、与报告级 judge 分的相关、以及它对不同写作风格（多引 vs 少引）的敏感性。否则评委会问「这个指标是不是只奖励多打引用」。
→ 修法：tab_annot（链 56 H4）要包含「指标 vs 人工」的混淆矩阵；再加一列「每篇引用密度」说明不是靠多引。

## R2 · 归因 / 引用生成专家（WebGPT、GopherCite、ALCE 一脉）

**R2.1 闸只查「引句在原文里」，不查「引句支持论断」。** 这是最容易被打的点。按构造成立的性质只保证可追溯，不保证正确。需要 ALCE 风格的**引用精确率 / 召回率**人工评估：对 PSV 和 ReAct 各抽 300 条（句子，引用）对，标注「完全支持 / 部分 / 不支持」。
→ 预期：PSV 的「不支持」应明显更低，因为写作者只见已核验卡；但这要用数据说，而不是用命题推。

**R2.2 核验器的误拒。** 删卡率 0.3–11.2% 被当成「引句幻觉率」，但其中一部分可能是归一化失败（OCR 连字符、全角 / 半角、变音符号、省略号切片）。
→ 修法：每模型随机抽 50 张被拒卡人工分类：真幻觉 / 近似改写 / 归一化误拒。报告误拒率；如果 > 10% 的拒卡是误拒，要改归一化并重算。

**R2.3 逐字引句排除了哪些证据。** 表格数字、尺寸、图像、翻译文本、需要综合两句才能成立的论断——这些在艺术史记录里很常见。
→ 修法：统计侦察员「读了却无卡」的文档里有多少是金文档（这正是上一会话提议的金文档漏斗），并抽样说明原因。

**R2.4 幽灵引用可能是对的。** ReAct 从检索摘要就能看到文档 id 与标题，不打开也可能引对。「2–13% 的得分落在没打开的来源上」要区分「不可核验」与「错误」。
→ 修法：对幽灵引用抽 100 条，标注其论断是否被该文档支持。然后把论点明确写成「不可审计」而不是「错误」；博物馆场景下不可审计本身就是失败，这句要说透。

## R3 · 智能体 / 系统评委（ReWOO、LLMCompiler、多智能体）

**R3.1 基线对等性。** ReAct 是否拿到同一份目录、同一套检索工具、同一套提示工程投入？预算（步数 / token / 900 秒）怎么定的？91–95% 被迫收尾说明预算在起作用，「ReAct 2×」对照是对的，但还要一条**预算敏感性曲线**（0.5× / 1× / 2× / 4×）而不只是一个点。
→ 修法：在 Drafts48 的 12 题子集上跑 4 档预算，画「打开文档数 / 金召回 / 落地召回 vs 预算」。

**R3.2 结构还是并行？** PSV 读 3 倍文档，是因为结构还是因为并行给了它更多「阅读额度」？需要一个把并行和结构拆开的混合基线：ReAct 但允许一次并行打开 K 篇（「ReAct-parallel」）或 ReAct 被强制先读规划器点名的清单（「ReAct-with-plan」）。
→ 修法：至少跑其中一个；如果 PSV 仍领先落地召回，说明闸和卡（而非阅读量）是关键。「只是读得多？」那一节现在用的是什么对照，核对。

**R3.3 PSV 的失败模式。** 规划器回退 1–2 例是什么情况；侦察员超时 / 工具报错怎么处理；覆盖修订带来多少收益、多少 token。
→ 修法：方法节加「失败与回退」小节；消融表里覆盖修订单列。

**R3.4 耗时的说法要克制。** 3/6 模型更快，GPT-Luna 上更慢（因为 ReAct 早停）。「耗时 = 规划 + 最慢侦察员 + 写作」是对的，但要用 tab_roles 的串行和 / 实际耗时来证，并写明同一网关、同一时段。

## R4 · 深度研究评测作者（DeepResearch Bench / LiveResearchBench 视角）

**R4.1 协议能否走出冻结语料。** 轨迹审计只需要两样东西：打开集合（工具日志）和句级引用。对开放网页代理，打开集合可得、文档会变。要写一节「如何在开放网页上应用」：抓取快照 + 哈希；对闭源产品不可用是本质限制，作为对商用系统的呼吁写出来。

**R4.2 单一评审模型。** judge = gemini-2.5-pro；要报：位置偏置（交换顺序重判一遍子集）、长度偏置（PSV 报告更长，judge 分是否随长度涨）、judge–人工一致率（tab_annot）。如果 judge 对长度有偏，就要在「评判分持平」前加一句「在长度校正后仍持平」。

**R4.3 评分 rubric 的细节与开源。** 把 judge 提示、rubric、打分示例放附录并开源。

## R5 · 数字人文 / 艺术史领域专家

**R5.1 任务真实性。** 48 + 199 道 brief 是谁写的、来自什么工作流（策展说明？藏品研究报告？）、是否经博物馆从业者审过。
**R5.2 逐字引句与学术习惯。** 艺术史写作以转述与综合为主、直接引用少。要说明：卡片是**证据层**，报告仍可转述；引用指向卡，卡再指向原文。读者会误以为报告满是引号。
**R5.3 可审计性的人类证据。** 「核一条引用只读一张 ≤120 词的卡」是论文最有博物馆价值的卖点，但现在是推论。请 3–5 位有馆藏经验的人各核 20 条引用（PSV vs ReAct 混排、盲评），记录每条核验耗时与成败。这是本稿最便宜、最能打动领域评委的一个实验。
**R5.4 图像版权与发布。** 冻结语料里的馆藏图像能否随数据集发布；写清许可。

## R6 · 统计 / 方法学评委

**R6.1 只报中位数、不报离散。** 每个主数字（token 比、耗时、打开文档、金召回、幽灵引用）给 IQR 或 CI。
**R6.2 多重比较。** 6 模型 × 多指标 × 2 数据集，要先声明主指标（句内落地召回）与主假设，其余为次要 / 探索性；或做 Holm 校正。
**R6.3 运行间方差。** 同一模型重跑 3 次（哪怕只在 12 题上），给出「跑与跑之间」的差异，否则读者不知道 10–15 分里有多少是采样噪声。
**R6.4 预算设定的理由。** 900 秒 / 步数 / token 上限是怎么定的，是否偏向任何一方；放到附录。

## R7 · 可复现性 / 工件评委

**R7.1 模型快照。** Claude-Haiku-4.5、GPT-5.6-Luna、Gemini-3.8-Flash、MiMo-Pro/Flash、Qwen3.8-Flash：写清确切版本字符串、调用日期、温度、是否经过网关、网关是否改写请求。网关名字出现在论文里会引起疑问，建议写成「通过 OpenAI 兼容网关转发到官方端点」并给出验证方式（例如响应头里的模型 id）。
**R7.2 发布清单。** 冻结语料（或可重建脚本）、所有轨迹、judge 提示、核验器代码 + 单元测试（含归一化、省略号切片、区域成员的用例）、一键重算所有表的脚本。
**R7.3 确定性核验器要有测试。** 20 个用例就够，覆盖：全角标点、连字符换行、省略号跨段、重复引句、区域不存在、视图编号越界。

## R8 · 多模态 / 视觉评委

**R8.1 「据我们所知第一个把核验延伸到图像区域」要收。** 已有工作：VISA（Visual Source Attribution，2024，用文档截图中的边界框作为引用）、面向文档图像的区域级归因、以及 GUI/文档 VQA 的区域证据。建议改为：「据我们所知，第一个把区域成员检查作为研究智能体**轨迹级闸**的一部分（而非生成时的标注）」，并引 VISA。
**R8.2 图像证据的量。** 多少任务需要图像区域、每篇报告平均多少区域引用、去掉视觉侦察员后的落差（消融的效应量），否则这一支看起来是装饰。
**R8.3 区域成员检查太弱。** 区域 ∈ 已渲染视图只保证「这个区域存在且被看过」，不保证区域内容支持论断。要和 R2.1 一样用人工抽样说支持率。

## R9 · 形式化 / 理论评委

**R9.1 命题 1 是按构造成立的恒等式。** 这没问题，但要坦率写成「设计保证（design guarantee）」，把假设列全：写作者输入只有卡；引用必须指向卡 id；核验是确定性的；不存在绕过通道（例如写作者的常识不能被当作引用）。
**R9.2 命题 2 的线性 / 平方要写假设。** ReAct 的平方依赖「上下文不截断、不摘要」；带记忆压缩的 ReAct 不满足。应加一条基线或至少一句讨论：「ReAct + 上下文摘要」是另一条省 token 的路，它的代价是什么（摘要本身会丢引句，正好与本文论点呼应）。
**R9.3 命题 3 的「约 10 次调用」是设计常数不是定理。** 写成「有界：≤ 2 + K + 2 次」并说明 K 的来源。
**R9.4 落地召回不是 100%，PSV 的失败在哪。** 既然引用一定可追溯，为何句内落地只领先 10–15 分而非压倒？应有一张 PSV 落地失败的分类表：卡不支持句子 / 句子综合了多张卡只引一张 / 写作者改写过度 / 金证据没进卡。这张表同时回答 R2.1 与 R2.3。

## R10 · 领域主席 / 「新在哪」怀疑者 + 写作

**R10.1 篇幅。** 英文 69 页对 IPM 偏长。主文控制在 35 页以内：tab_expmap、tab_roles、tab_growth、相关工作对照表的完整版、全部消融细表移到附录或补充材料；主文每个 RQ 只保留一张表 + 一张图。
**R10.2 主线要一条直线。** 引言的叙事只能是：仪器（冻结语料 + 轨迹审计）→ 发现（评判分看不出的 2–13% 幽灵得分与 10–15 分落地差）→ 参照设计（PSV 把它变成不变量）。凡是不在这条线上的段落都往后挪。
**R10.3 命名统一。** verify-before-write、verified evidence card、phantom citation、trajectory-grounded citation 四个词，全文每处都用同一个写法；中文稿同样固定四个译名。
**R10.4 软化的措辞。** 「第一个」只留 R8.1 改过的那一条；「by construction」每节最多出现一次；加一个「PSV 不做什么」框（不保证正确、不中途改计划、不处理开放网页）。
**R10.5 图 1。** 把 teaser（硬负例 5/5 读过 vs 0/5 读过却被引 5 条）画成图 1，比任何文字都快。

## 汇总：优先级清单

### A. 投稿前必须（都不需要新 API 实验，或只需人工标注）
1. 全部主数字加配对 bootstrap CI；「平」用 TOST 写（R1.1、R6.1、R6.2）。
2. 引用支持率人工评估：PSV / ReAct 各 300 条（R2.1、R8.3、R9.4）。
3. 拒卡误拒审计：每模型 50 张（R2.2）。
4. 幽灵引用「不可审计 vs 错误」抽样 100 条，并改写论点措辞（R2.4）。
5. 「第一个延伸到图像区域」改口并引 VISA（R8.1）。
6. 命题改为「设计保证」并列假设；加「ReAct + 上下文摘要」讨论（R9.1–R9.3）。
7. 篇幅砍到 35 页主文，叙事一条直线，命名统一，加「不做什么」框，teaser 变图 1（R10）。
8. 模型版本 / 网关 / 预算设定写进附录；核验器单元测试随代码发布（R7、R6.4）。

### B. 强烈建议（少量 API 或少量人工）
9. 预算敏感性曲线（12 题 × 4 档）（R3.1）。
10. 拆开并行与结构的混合基线：ReAct-parallel 或 ReAct-with-plan（R3.2）。
11. 策展人核验耗时小实验：3–5 人 × 20 条（R5.3）——性价比最高的一项。
12. judge 位置 / 长度偏置检查（R4.2）。
13. 同模型重跑 3 次（12 题）给运行间方差（R6.3）。
14. PSV 落地失败分类表 + 金文档漏斗（R9.4、R2.3）。

### C. 锦上添花
15. 第二个领域的小规模迁移（例如地方志 / 法律判例）或至少一节「如何迁移」（R4.1）。
16. 图像证据的量化小节（R8.2）。
