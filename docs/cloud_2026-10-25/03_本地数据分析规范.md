# 本地数据分析规范（零 API，可直接实现）

> 这些分析只需要本机已有的 results.jsonl、轨迹、卡片、plan.json 和冻结语料，不需要再调模型。
> 我这边读不到本机数据，无法核实字段名，所以每条写成「输入 → 逻辑 → 输出 → 自检」，字段名用占位符，实现时对照真实 schema 替换。每条都标了它回答评委清单（`01_十位评委模拟评审.md`）里的哪一项、以及替换模拟（`sim/`）里的哪个参数。

---

## A1 · 配对 bootstrap 置信区间与等价性检验 —— 回答 R1.1 / R6.1 / R6.2

**输入**：每个（数据集, 模型）格位里 PSV 与 ReAct 的逐题指标：judge 分、句内落地召回、幽灵得分比例、token、耗时、打开文档、金读到率。
**逻辑**：
1. 以题为重抽样单位，配对差 Δ_i = PSV_i − ReAct_i；bootstrap 10,000 次，报均值差的 95% 百分位 CI；同时报配对 Wilcoxon p 值与效应量（Δ 的均值 / Δ 的 SD）。
2. 对 judge 分做 TOST：等价边界 ±δ（建议 δ = 3 分，占满分 100 的 3%；在正文里声明），两个单侧检验的 p 都 < 0.05 即判「等价」。
3. 多重比较：预先声明主指标 = 句内落地召回、主假设 = PSV > ReAct；其余指标标注为次要 / 描述性。若要校正，用 Holm。
**输出**：`tables/tab_ci_{dataset}.tex`：每格位一行，列 = 指标、Δ 均值、95% CI、p、效应量、TOST 结论。
**自检**：CI 不包含 0 的格位数应与现有主表的「胜 / 负」判断一致；若不一致，以 CI 为准改正文。

## A2 · 词法预筛回溯曲线 —— 决定变体 V2，替换 `prescreen_tau`

**输入**：所有 PSV 轨迹里每个被侦察的文档 d、规划器给该子问题的检索词 q（plan.json 的 queries 字段）、该文档是否产出通过核验的卡、该文档是否为该题的金文档。
**逻辑**：
1. 对每个 (q, d) 计算 BM25（或简单的词项重叠率：|terms(q) ∩ terms(d)| / |terms(q)|，用同一套归一化：小写、去标点、全角转半角）。
2. 对 τ 从 0 到 0.8 步进 0.05：剔除率_零卡 = 分数 < τ 的零卡文档数 / 零卡文档总数；保留率_金 = 分数 ≥ τ 的金文档数 / 金文档总数；同时算「省下的侦察 token」= 被剔文档的输入 token 之和 / 侦察总 token。
3. 选 τ* = 使保留率_金 ≥ 0.98 的最大 τ。
**输出**：`runs/_prescreen_retro.md` + 一张双曲线图。
**自检**：τ = 0 时剔除率必须为 0；金文档中分数为 0 的数量要列出来逐个看（通常是别名 / 多语言问题，这是 V2 的真实风险）。
**决策规则**：τ* 下省 token ≥ 15% → V2 值得真跑；否则放弃。

## A3 · 金文档漏斗 + 提及计数 —— 回答 R2.3 / R9.4，替换 `mention_p` 与 `p_card_gold`

**输入**：每题金文档集合 G；plan.json 点名的文档集合 N；侦察员实际打开集合 O（工具日志）；卡片集合 C（含 doc_id、是否通过核验）；最终报告引用集合 R。注意 plan 里的编号与卡片 doc_id 要先统一到同一套 id（别名表）。
**逻辑**：对每篇金文档 g 标记五级：① 被规划器点名 (g ∈ N)；② 被打开 (g ∈ O)；③ 出卡 (∃c ∈ C, c.doc = g)；④ 卡通过核验；⑤ 被引用 (g ∈ R)。按模型、按数据集报每级的份额（相对 |G|）。
**提及计数**（V4 的前提）：对每篇「未被打开的金文档」g，检查是否有任一**已打开**文档的原文中出现 g 的馆藏号 / 标题 / 文献 id（用冻结语料做字符串匹配）。报「被提及未打开的金文档 / 未打开的金文档」比例 = 跟随提及最多能补回多少。
**输出**：`tables/tab_funnel.tex`（漏斗）、`runs/_mention_count.md`（比例 + 每题明细）。
**自检**：五级份额必须单调不增；① 的漏失份额应与正文已写的「40% 归于计划没点」在数量级上吻合。
**决策规则**：被提及未打开的金 ≥ 30% → V4 值得真跑；< 10% → 放弃 V4 和 V5。

## A4 · PSV 句内落地失败分类 —— 回答 R9.4 / R2.1

**输入**：PSV 报告里每个「未落地」的句子（按协议判定）及其引用的卡。
**逻辑**：随机抽 150 条，人工（或先用规则预分）归入：(a) 句子综合了多张卡但只引了一张；(b) 卡的引句不支持这句（写作者过度推断）；(c) 写作者改写过度导致匹配失败（指标假阴性）；(d) 该句本应引的金证据没有进卡（漏斗③④的后果）；(e) 其它。
**输出**：一张小表 + 每类两个例子（附录）。
**用途**：(c) 的比例是指标的假阴性率，要写进效度包；(a) 提示写作者提示里要加「多卡合引」；(d) 把方法的上限与漏斗连起来。

## A5 · 拒卡误拒审计 —— 回答 R2.2

**输入**：核验器拒掉的全部卡（含被拒原因：引句未命中 / 区域不存在 / 编号无效）。
**逻辑**：每模型随机抽 50 张引句未命中的卡，人工分三类：真幻觉（原文无此句）/ 近似改写（意思在、字不对）/ 归一化误拒（原文有、但连字符 / 全半角 / 省略号切片导致未命中）。
**输出**：`tables/tab_gate_audit.tex`。
**自检**：若「归一化误拒」> 10%，修归一化并对全部卡重跑核验器（确定性，几秒）；重跑后 tab_gate 与所有下游表要重算——这是确定性闸的优势，要在正文里点一句。

## A6 · 幽灵引用：不可审计 vs 错误 —— 回答 R2.4

**输入**：ReAct 报告里引用了未打开文档的 (句子, 文档) 对。
**逻辑**：抽 100 条，对照冻结语料人工判断该文档是否支持该句。
**输出**：比例 + 论点措辞。若多数幽灵引用「碰巧对」，正文把论点从「错误」改成「不可审计且无法区分对错」；若多数错，论点更强。两种结果都能写。

## A7 · 核验器计时 —— 支撑「只需微秒」

**逻辑**：对全部 23,734 张卡重跑 verify_quote 与区域检查，计时；报每张卡的中位 / p99 微秒数与总耗时。
**输出**：正文一句话 + 附录一行。

## A8 · 策展人核验耗时小实验 —— 回答 R5.3（需要 3–5 位人）

**设计**：从 PSV 与 ReAct 报告各抽 20 条引用，混排、盲评；每位参与者对每条：找到支撑证据或判定找不到；记录耗时与结论。PSV 给卡（≤120 词）+ 原文链接；ReAct 给文档链接。
**输出**：每条中位耗时、成功率、参与者间一致率。预期 PSV 的核验耗时显著更短——这是「可审计」的直接人类证据，也是博物馆读者最在意的一个数。

## A9 · judge 偏置检查 —— 回答 R4.2

**逻辑**：在 Drafts48 的 12 题 × 2 模型子集上：(1) 交换 PSV / ReAct 的呈现顺序重判，看分差是否翻转；(2) 回归 judge 分对报告长度（词数）的斜率，分别对 PSV 与 ReAct；若斜率显著，报告长度校正后的分差。
**输出**：附录一张小表。注意这条需要评审通道恢复（gemini-2.5-pro）。

## A10 · 运行间方差 —— 回答 R6.3

**逻辑**：12 题 × 1 模型（建议 MiMo-Pro）× 3 次重跑，PSV 与 ReAct 各自；报每个主指标的跑间 SD。需要 API，但量很小（72 次运行）。
**输出**：正文一句「跑间 SD 为 x，小于 PSV–ReAct 的差 y」。

## 实施顺序建议

1. A1（纯统计，半天）→ 所有主表立刻有 CI。
2. A3（漏斗 + 提及计数）→ 决定 V4 要不要做；它同时回答两位评委。
3. A2（预筛回溯）→ 决定 V2。
4. A5、A6、A4（人工抽样，各 1–2 小时）→ 效度包。
5. A7（几分钟）。
6. A8、A9、A10 视人手与评审通道情况安排。
